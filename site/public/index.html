A task tracker for people and coding agents

Toodo tracks planned work: the dependencies between tasks, and the notes, decisions, and status history of each one. It runs on your own server.

$ npx @dubusoft/toodo init

Features

Toodo tracks the work; it doesn't run it. You or your agents do the work wherever you like, and record its start, progress, and completion in Toodo.

  • Dependencies as a DAG

    Tasks depend on other tasks, and a dependency that would create a cycle is rejected. A task is ready once every task it depends on is done, and it completes when its criteria pass: checked by hand, or by a URL that Toodo fetches.

  • Work memory

    Each task keeps its progress, decision, and blocker notes, a completion note, and references such as pr:<url>. Starting, pausing, and completing a task each record why.

  • Timeline

    Every status change is timestamped, and the timeline draws the dependency graph on a time axis: when each task was planned, started, reviewed, and completed.

  • MCP for coding agents

    Coding agents connect to the server's MCP endpoint to plan tasks, record starts, notes, and decisions, and complete their tasks. The agents guide shows how a lead agent and its workers use it.

  • Review report

    Review shows what was planned, started, and completed in a week, month, quarter, or year, built only from recorded facts. Copy it as Markdown, save it as Markdown or CSV, or print it.

  • A web app on your own server

    toodo-server runs on your Linux machine and serves the web app: open it in any browser, or install it as an app on a desktop or a phone. Tasks and their history stay in a SQLite database on that machine.

Get started

Requirements

  • Linux on x64 or arm64, with glibc
  • Node.js 18 or later, with npm

Install and start the server

npm i -g @dubusoft/toodo
toodo init
toodo service install

toodo init creates the data directory, starts the server, and registers its MCP endpoint with Claude Code and Codex when they are installed. It prints the web app URL and the file that holds the access token.

toodo service install keeps the server running as a systemd user service, also after a reboot.

Plan a first task

Sign in with that token, add a workspace, and plan a task: the quickstart walks through each step. To open the web app from other devices, put the server behind a tunnel, as the server guide describes.
