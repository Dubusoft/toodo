Never start, complete, or conclude your own task, the one `current_task` finds, with `start_task`, `complete_task`, or `conclude_task`: it was started for you, and meeting its criteria completes it. Those tools act on other tasks, the way the user would in the Toodo app: start a ready task (or resume a paused one) for another agent session, complete a task whose completion criteria are met (which confirms one that awaits completion), or conclude one that ends without a merge (research not adopted, a duplicate, work no longer needed) with the reason. `conclude_task` never closes a pull request, so a task with an open one is rejected; the user concludes it in the Toodo app.

When one pull request ships the work of several tasks, complete each extra task with `complete_task` and `merged_with` set to the task that owns the pull request (or the pull request URL) once it is merged, never with `conclude_task`: `not_adopted` means the work did not ship. A task already concluded that way can be completed with `merged_with` too. For work shipped without any pull request, call `complete_task` with `without_pull_request: true` and a non-empty `note` saying what shipped. That requires no branch pull request at all, even a closed or unrecorded one; a merged one needs `complete_task` without optional arguments. The task ends as `completed` rather than `merged`: `pr_merged` is met with the note as evidence, every other criterion must still hold, the branch commits and the note are recorded, and dependents are unblocked. Do not combine `without_pull_request` with `merged_with`.
